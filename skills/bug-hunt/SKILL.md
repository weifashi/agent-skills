# 提测检查：找问题，给出能不能提测

**每条问题都要有证据，结论放最前，找到的问题记进项目。** 不报风格偏好，不报「可能有问题」的猜测；宁可少报，不报查不实的。

## 1. 定范围、读材料

- **范围**：默认是当前分支相对主干的全部改动，加上未提交的改动（`git diff <主干>...HEAD` + `git status`）。用户点名了模块或「整个项目」就按用户的。
- **需求**：读项目 `docs/background/`（需求原文）和 `docs/decisions.md`。没有这两样时，从 issue、PR 描述、用户这次的话里找要求，并在结论里写明「需求依据不全」。
- **已有清单**：读 `docs/bugs.md`（没有就照 `assets/bugs.md` 新建）。里面的「已查范围」告诉你上一轮查到哪；已经记过的问题不再报。

先把需求原文拆成一条条**可核对的要求**，后面逐条标：满足 / 部分满足 / 没满足，各带证据。

## 2. 按六类查

| 类别 | 查什么 |
|---|---|
| **没满足需求** | 逐条对照要求：漏做的、做偏的、只做了顺利路径的、和已定决策冲突的 |
| **业务逻辑** | 判断条件、边界值、状态流转、金额和数量计算、默认值、时区、错误分支、空值 |
| **并发** | 重复点提交、重复请求、两人同时改同一条、先查后改没加锁、没有幂等键、事务范围不对、重试导致重复执行 |
| **性能** | 循环里查库（N+1）、不分页全量查、缺索引、大循环里做重活、同步调慢接口、重复请求、前端一次渲染大量节点 |
| **内存 / OOM** | 一次把全表或大文件读进内存、无上限的缓存和队列、没释放的监听 / 定时器 / 连接、无限增长的集合、大对象反复拷贝 |
| **界面** | 布局错乱、溢出、遮挡、截断、对不齐；宽屏和窄屏；空数据、数据很多、文字很长；加载中、失败、无权限时的样子；和原型（`docs/mockups/`）不一致的地方 |

- 能并行就并行：按类别或按目录分给几个子代理同时查，每个拿完整的改动片段，不是摘要。**子代理报回来的每一条，自己读代码核实后才能记**；两条线结论打架时也自己读代码定。
- **界面要实际打开页面看**，并截图。项目跑不起来时照实写「界面未实际查看，只读了代码」，不拿读代码冒充看过。
- 能复现的就复现：写个小测试或跑一下，标「已复现」；只是读代码看出来的标「读代码」。

## 3. 每条问题怎么记

记进 `docs/bugs.md`，格式见 `assets/bugs.md`。每条必须有：

- **位置**：`文件:行号`，界面问题写「哪个页面、什么宽度、什么数据」
- **怎么触发**：什么操作、什么条件下出错（写到别人能照着复现）
- **影响**：谁会遇到、后果是什么
- **依据**：已复现 / 读代码
- **建议改法**：一句话

严重程度：

| 级别 | 标准 |
|---|---|
| **高** | 数据错或丢、钱算错、崩溃 / OOM、主流程走不通、明确的需求没满足 |
| **中** | 特定条件下出错、明显变慢、界面错乱影响使用 |
| **低** | 不影响使用的小瑕疵 |

同一个原因造成的多处表现记成一条，列出各处位置。上一轮已经记过的不重复记。

## 4. 每 50 条停一次

新记满 50 条就停；范围查完了不足 50 条也停。**不为凑数硬找**。停下时按这个顺序汇报：

1. **结论**：✅ 可以提测 / ❌ 不能提测。有「高」或有没满足的需求就不能提测；列出挡住提测的那几条。
2. **需求核对表**：每条要求满足了没有。
3. **这一批的问题**：按严重程度排的表（编号、级别、类别、位置、问题、建议改法）。
4. **查了什么、没查什么**：哪些目录和页面查过，哪些没查到、为什么。
5. **等用户决定**：修哪些 / 继续找下一批 / 就这样提测。

然后**停下**，不自己开始修，也不自己接着找。

## 5. 用户决定之后

- **修**：只修用户点名的。修完把状态改成「已修」，并重新验证那一条确实好了。
- **不修**：状态改成「不修」并写用户给的原因，以后不再报。
- **继续找**：从「已查范围」之外接着查；先抽查上一批「已修」的有没有改出新问题。
- 配合 `/loop` 反复跑时，每一轮都按第 1 节重新读 `docs/bugs.md`，所以不会重复报。

## 易错点

- 把代码风格、命名、「可以更优雅」当 bug 报 —— 不报。
- 子代理说有问题就直接记 —— 先自己核实。
- 没打开页面就说界面没问题 —— 没看就写没看。
- 发现问题顺手就改了 —— 用户要的是先看清单再决定。
- 只查顺利路径 —— 空数据、超长、重复点、断网、没权限都要走一遍。
- 没读需求原文就判断「功能正常」 —— 能跑不等于满足要求。
