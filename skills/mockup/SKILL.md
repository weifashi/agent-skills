# 一页 HTML：需求原型 / 高保真效果图 / 改动汇报

**一页 HTML 讲清一件事。** 不是界面图集，是「说明书 + 图」混排：该画的画出来，规则写在旁边，这次改的标绿。对方打开就能看懂、能评审、能拍板。

## 先选用法

| 用法 | 讲的是 | 起手 | 细则 |
|---|---|---|---|
| **A 需求原型** | 要做成什么样、几个方案怎么选 | `assets/template.html` + `assets/blocks.html` | 本文件；选积木读 `references/blocks.md` |
| **B 改动汇报** | 已经改了什么、动了什么、谁受影响 | 同上，正文栏用 `.wrap rep` | **做之前必须读 `references/change-report.md`** |
| **C 高保真效果图** | 做出来长什么样、怎么一步步用（给老板、客户） | `assets/hifi.html` | 读 `references/hifi.md` |

A 和 C 可以合在一页：方案章节按 A 写，界面章节用 C 的零件。要真能提交数据、要 1:1 对齐线上组件的，不走本技能。

## 存哪、怎么给人看

1. **正本存进项目**：`docs/mockups/<slug>/index.html`（改动汇报用 `<slug>-changes`）。slug 用功能的英文短名，不带版本号和编号。进不进 git 按项目习惯；生成文件不等于获准提交。
2. **同一件事只有一份**：先 `ls docs/mockups/` 看有没有旧的，有就改那一份，别新建。改版在页头下加绿色「本次更新」框，每条带锚点。
3. **给人看**，按顺序用第一个可行的：
   - 客户端有对话内预览工具（如 `preview_html`）：直接弹出来。
   - 用户的规则里写了预览服务（地址、目录）：按那里的做法给**公网链接**，完整地址明文贴出，改过就带 `?v=N`，发之前 `curl` 确认 200。
   - 都没有：给项目里的文件路径，说明双击就能打开。
4. **不自作主张**起服务、开公网端口、上传到外部。没有可用的链接就明说没有，不编。

## 硬规矩

- **单文件、零外部依赖**：CSS 内联、系统字体、图标用 Unicode 字符（高保真用组件库自带的内联图标）、图用内联 SVG。不引 CDN、外部字体、外链图片、mermaid.js。`<a href>` 是导航，不算。
- **从 `assets/template.html` 复制起手**，不照旧页面抄 `<style>`：旧页面带着它生成那天的过时样式，看着正常，没人会发现。旧页面只抄内容结构。
- **先查真实素材再画**：需求原话（先看项目 `docs/background/`）、现有界面长什么样、字段和状态的真名。凭印象画的界面，对方一眼看出不是他的系统。没核实的标「待确认」。
- **界面帧里只放界面上真有的字**，解释写在 `.hint` 块里，不冒充界面文案。
- **正文 16px 起**，不缩字塞内容；要紧凑就减内容。
- **状态机、调用链必须是真正显示的图**，只贴 mermaid 源码等于没画。

### 颜色有固定含义

| 用法 | 颜色 |
|---|---|
| 现状、已有的 | 灰白常规样式 |
| 这次新增 / 改的 | 绿 `#16a34a`（`.tag-new` 徽标 / `.newf` 绿虚线框） |
| 主操作按钮 | 琥珀 `#f59e0b`（按项目品牌色调） |
| 编号、强调 | 橙 `#ea580c` |
| 警告 / 失败 / 破坏性 | 红 `#dc2626` |
| 删掉的 | 红 + 删除线 |

读者第一件事是分清「哪些现在就有、哪些是这次要加的」，绿色就是干这个的。整页浅色，**只有 mermaid 图用黑底**。

### 宽度

| 页面 | 正文栏 |
|---|---|
| 需求原型（界面帧 + 说明为主） | `.wrap`，900px |
| 改动汇报、调查报告（规则卡 + 表格 + 双栏为主） | `.wrap rep`，跟着屏幕长，上限 1920px |
| 画完整后台外壳的原型 | `.wrap desk`，1180px |

- 900 栏里的宽内容（并排双栏、宽表、宽 ASCII 树）加 `.bleed` 挣脱；`rep` 里不用加。
- 文字块已限制行长（约 48 个汉字），所以栏宽了文字也不会变成一长条。
- 同一页里最窄和最宽的内容块别差一倍：每块单独看都对，摞在一起会断层。

### ASCII 和 mermaid

- ASCII 放 `<pre class="ascii">`，**框线里只放半角**（表名、字段名、文件名）；中文放框外或右侧 `#` 注释。
- mermaid 按积木 L 写源码卡，源码第一行带深色主题（积木里有现成的）；源码里的 `<br/>` 写成 `&lt;br/&gt;`。写完跑渲染器。

## A 需求原型

1. **定名、查旧的**（见上）。
2. **拼页面**，骨架固定：
   - 页头：功能名 + 一句话说清这版讲什么 + 日期 + 「方案 · 未实施」
   - 方案页、调研报告：第一节放「一页看懂」（积木 0：结论、关键数字、给谁用、下一步）
   - 界面超过 3 个：加吸顶的锚点导航
   - 第二版起：绿色「本次更新」框
   - 分节：一节一件事，标题下写「从哪进 / 什么时候看到」；每条规则写清 **页面 → 操作 → 结果**
3. **先按「要表达什么」选积木**（`references/blocks.md`），很多需求用流转图、矩阵表、时间线讲，比堆界面清楚。抄积木时连它的 CSS 一起抄。
4. 方案就是方案：不写「已上线」「验证通过」，不写实际没改的表字段。
5. 给几个方案挑时：并排画出来 + 一张对比表 + 写明推荐哪个、为什么。

## B 改动汇报

完整手册在 `references/change-report.md`。不能违反的几条：

1. **不漏**：以 `git diff --name-status` 的文件清单为底账，每个文件都出现在 S1 的 ASCII 树里；收尾核对集合一致。
2. **逐行看，不看摘要**：每处改动归到「规则变化 / 无规则影响 / 待确认」，纯重构不编成规则变化。
3. **能并行就并行**：六条线分给多个代理同时采集；派不了就分批做并如实说。结论打架时自己读代码复核。
4. **四块必有**：表字段、原规则 → 新规则、影响哪些业务点、怎么回滚。没有变化的写「无」。
5. **每条改动落到「页面 → 操作 → 改前 / 改后」并把页面画出来**。用户确实无感知时也写这三行，说明变的是什么。

## 检查（交付前必跑）

`<技能目录>` 是本文件所在目录。

```bash
python3 <技能目录>/assets/hifi/inline.py <页面>           # 只有用了高保真零件才跑
python3 <技能目录>/scripts/render-mermaid.py <页面>       # 有 mermaid 卡才跑；先渲染再量
python3 <技能目录>/scripts/check-overflow.py <页面> --screenshots=<截图目录>
```

- 溢出检查默认量 390 / 768 / 1440 三种宽度（`--widths=` 可改），实际宽度没量到、浏览器起不来都算失败，不会假通过。需要本机 Chrome 和 Node 22 以上；缺了就照实说「未验证」。
- 渲染器最后一行会报「渲染 N」，N 要等于图的张数；再打开页面确认每张图都显示成了图。
- 溢出检查报撑破：给那几个元素加 `.bleed`，或包进可横向滚动的容器。
- 渲染 mermaid 需要 `mmdc`（`@mermaid-js/mermaid-cli`）和本机 Chrome。缺了它不会改坏页面，但图也没画出来：照实说「图未渲染」，要不要安装先问用户。
- **命令通过不等于看过**：截图或打开页面，电脑和手机宽度各看一遍。要截图 / 转 PDF 时不用彩色 emoji（很多机器没有字体，会变成方块），用 ① ★ ▼ › ✓ ✕ 这类符号。

## 交付

说清：存在哪（项目内路径）、是方案还是已实施的改动、检查跑了哪些、哪些没验证。有链接就把**完整地址明文写出来**，不藏在链接文字后面；提到某个界面说它的名字或给锚点，不说「图 1 / 图 2」。

## 易错点

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 同一需求新建一个目录 | 对方手里的旧链接还是旧内容 | 改原来那份；真要合并，旧目录留一个跳转页 |
| 照旧页面抄 CSS | 过时样式一起继承，看不出来 | 从模板起手 |
| 凭印象画现有界面、自己编字段名 | 对方一眼看出不是他的系统 | 先查代码和截图，用系统里的真名 |
| 界面帧里写讲解文字 | 对方以为那些字是界面上的 | 解释放 `.hint` |
| ASCII 框线里混中文 | 浏览器里必然错位 | 框内只放半角 |
| 只贴 mermaid 源码 | 手机上是一坨代码 | 跑渲染器，核对图数 |
| 抄了两个积木，样式互相串 | 后代选择器压不住顶层同名类 | 抄之前搜一下类名有没有撞（`references/blocks.md`） |
| 改动汇报只讲改了什么 | 评审看不出风险 | 表字段 / 规则 / 业务点 / 回滚，缺一不可 |
| 给 `localhost` 或内网地址 | 对方打不开 | 只给确认过能访问的公网地址，否则给文件路径 |
| 原型只留在预览里或临时目录 | 以后找不到 | 正本在项目 `docs/mockups/` |

改脚本、改模板时的注意事项见 `references/maintenance.md`（只有维护本技能时才读）。
