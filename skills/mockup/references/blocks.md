# 积木索引

**先按「要表达什么」选积木。**能画成图的不写成字:一节一张图,字只做标注。

源文件:`assets/blocks.html`(浏览器打开直接看效果,连同它 `<style>` 里对应的那几条 CSS 一起抄进页面)。起手模板:`assets/template.html`。

| 你要表达什么 | 积木 | 类名 |
|---|---|---|
| **结论、关键数字、给谁用、下一步**(调研报告、方案页的第一节) | 0 一页看懂 | `.glance` |
| 一个弹窗 / 表单长什么样 | 手机弹窗帧 | `.phone` |
| 这功能挂在哪个端、哪个菜单、谁看得到 | A 桌面后台外壳 | `.shell` |
| 一批数据在哪看、怎么筛、每行能干什么 | B 业务列表页 | `.dt` |
| 票据 / 小票印出来什么样 | C 小票纸卷 | `.rcpt` `.amt` |
| 一条单据实际走过的路,谁几点做了什么 | D 操作轨迹时间线 | `.tl` |
| 这次做什么不做什么、我们有什么缺什么 | E 判定矩阵表 | `.mx` `.rmk` |
| **凡是「改」**:改前什么样、改后什么样(栏里放界面帧,改动处绿框) | F 并排双栏对照 | `.cols` |
| 一张界面图讲不完的 4~6 条后果 | G 三色要点卡网格 | `.cards` |
| 这一改会动多少东西、差多少钱 | H 旧→新差异清单 | `.diffl` |
| 哪块是新的、哪个值变了 | I 内联新旧标注 | `.tag-new` `.newf` `.old` |
| 有几种结局、每种能点什么 | 状态流转图 | `.flow` |
| 一个值改前改后 | 简单对比表 | `.cmp` |
| **一条业务规则怎么变的**(改动汇报) | J 规则卡 | `.rule` |
| **文件树 / 字段树 / 结构清单** | K ASCII 面板 | `pre.ascii` |
| **状态机 · 调用链**(唯一黑底) | L mermaid 黑底卡 | `.mmd` |
| **一次改动的关键数字**(N 文件 / M 表 / K 规则) | M 数字条 | `.stats` |
| 用户一步步怎么操作,每步一屏 | N 步骤条 | `.steps` |
| 比多少、差多少 | 条形图(在积木 0 里,可单独用) | `.bars` |
| 要对方定的事,一张卡一件 | P 待拍板卡 | `.asks` |
| 评审才查的细节(文件、字段、代码位置),默认收起 | Q 折叠细节 | `details.more` |

要画仿真的手机 / 平板界面、可点原型,用高保真组件库,见 `hifi.md`。

## 抄之前先搜类名有没有撞

后代选择器压不住顶层同名类:写了 `.mx .note` 也照样吃到 `.note` 的橙边框。已知三处已在积木库里改好名,别改回去:

- 列表页表格用 `.dt`,不是 `.tb`
- 小票小计用 `.amt`,不是 `.st`(`.st` 是分节)
- 矩阵说明列用 `.rmk`,不是 `.note`

「一页看懂」的样式全部收在 `.glance` 下面,不会和别的积木撞。
