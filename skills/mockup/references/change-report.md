# 改动汇报：手册

把一次任务的代码改动变成一页谁都看得懂的东西。读的人想知道三件事：**我会看到什么不一样、会不会出事、出事怎么退回去。** 所以正文是一张张「改前 → 改后」的图，文件、字段、代码位置这些细节默认折叠。

产出：项目里的 `docs/mockups/<slug>-changes/index.html`，正文栏用 `<div class="wrap rep">`。

## 1. 先立底账

```bash
BASE=$(git merge-base HEAD origin/main)        # 换成项目的主干分支，或用户指定的基线
git diff --stat $BASE...HEAD | tail -1          # 文件数和行数
git diff --name-status $BASE...HEAD             # 文件清单 = 底账
```

工作树里有未提交的改动时，把 `git status --porcelain` 的结果并进来。底账里的每个文件，最后都要出现在页面的文件树里，一个不少。

## 2. 采集

**默认自己读**：逐个文件读完整 diff（不是 `--stat`，不是摘要），每处改动回答四个问题：

1. 原来是什么规则，现在是什么规则？（规则 = 判断条件、阈值、状态流转、金额算法、权限、默认值、排序、时间窗口、错误分支）
2. 用户在哪个页面、做什么操作会走到这里？
3. 改前会怎样，改后会怎样？
4. 谁会受影响？

只是重命名、挪位置、格式化的，归为「规则没变」，不编影响。拿不准的标「待确认」，写清要问谁。

**改动大才分头查**（约 15 个文件或 800 行以上，且工具允许派代理）。一次发出去，每条线拿到的是基线、它负责的完整文件清单和完整 diff，并写明「不许只看 --stat 下结论」：

| 线 | 要交回什么 |
|---|---|
| 清点 | 每个文件一句大白话：干了什么、动没动规则 |
| 数据库 | 每个字段：表、字段、动作、旧定义 → 新定义、存量数据怎么办、回滚 SQL；有没有大表锁、和代码上线的先后 |
| 规则（主菜，文件多时按目录再拆） | 每处改动回答上面四个问题，带 `文件:行号` |
| 影响面 | 每个改了规则的函数被谁调用、属于哪个端、用户在哪一步碰到 |
| 接口和文案 | 接口的增删改、老客户端会怎样；新文案在各语言里补齐没有 |
| 风险 | 有没有测试、并发和事务上的隐患、回滚步骤（代码和数据分开写）、上线后盯什么 |

汇总时：两条线结论打架就自己读那几行代码定；重点查过、结果不成立的，也写一句「查过，不成立，因为 X」。

## 3. 页面怎么排

图在前，细节收起。每节先一句大白话结论。

| 节 | 放什么 | 画成什么 |
|---|---|---|
| 一页看懂 | 一句话：干了什么、用户能感觉到什么；N 个文件 / M 张表 / K 条规则 / 高风险 X 条 | 积木 0 + 数字条 M |
| **改了什么** | 每条改动一张卡，用户感知最大、风险最高的排前面 | **改前 / 改后左右并排两帧**（F，不上下摞） |
| 流程怎么变 | 状态流转、调用链有变化才要 | mermaid（L），变化的边写「【本次新增】」 |
| 谁受影响 | 哪个端、哪个角色、在哪一步碰到 | 矩阵表（E） |
| 风险和回滚 | 风险几条、回滚几步、上线后怎么验 | 三色卡（G）+ 步骤条（N） |
| 折叠细节 | 文件树（底账里每个文件都在，标出规则变没变）、表与字段明细和回滚 SQL、代码位置、接口和文案清单 | Q 里放 ASCII 树（K）和表格 |

### 「改了什么」每张卡的固定样子

```text
┌ 小标题：一句话说结论，例「超过 30 天的订单不能再退款」      [高风险]
├ 左：改前的页面帧            右：改后的页面帧（变化处绿框）
├ 页面 → 操作 → 结果：订单详情 → 点「申请退款」→ 改前直接能退；改后提示已超期、按钮变灰
└ 谁受影响：门店收银、财务                    （代码位置放折叠细节）
```

- 页面帧用系统里真实的页面名和字段。手机端用手机帧，后台用后台壳，列表用列表页。
- **没有界面的改动也画**：左右各放「同一个操作的结果」，例如改前「翻到最后一页 → 内存约 557MB，偶尔报错」，改后「同样操作 → 约 29MB，正常出数据」。不许只写一句「用户无感知」。
- 动了表结构：正文里画字段的改前 → 改后（字段树，新增的标绿），完整定义和回滚 SQL 进折叠。

## 4. 收尾自检

1. **不漏**：底账里的文件都在文件树里。
2. **每张卡**都有改前、改后两帧和「页面 → 操作 → 结果」，并且在折叠细节里有对应的 `文件:行号`。
3. **四样齐全**：表字段、规则变化、影响谁、怎么回滚。没有的写「无」。
4. 「待确认」的要么查清，要么单列出来写明问谁。
5. 照 SKILL.md「检查」跑完；遮住文字只看图，说得出改了什么。

## 5. 交付

```text
改动汇报：docs/mockups/<slug>-changes/index.html（有链接就贴完整地址）
一句话：<一页看懂里的结论>
动了 N 个文件 / M 张表 / K 条规则，高风险 X 条；回滚步骤在最后一节
```
