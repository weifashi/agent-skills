# 维护本技能时的注意事项

只有改脚本、改模板、批量改旧页面时才需要读。都是实际出过的问题。

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 批量改字号时连内联 SVG 一起改 | mermaid 图里节点框尺寸是渲染时定死的，字号一变文字就顶出框被裁 | 先把 `<svg>…</svg>` 抠成占位符，改完放回；图要变大就重新渲染 |
| 循环里改字符串，却用循环前算好的偏移量 | 第一次插入后后面的位置全错，只处理了一部分，而且不报错 | 倒序处理（`reversed(list(re.finditer(...)))`） |
| 拼接时既用了自带结尾换行的常量，又手动补 `"\n"` | 第二遍跑就少一行，不幂等且不报错 | 常量统一 `.rstrip("\n")` 后再拼；幂等性要连跑三遍比 md5 |
| 工具把自己的 CSS 塞进页面已有的 `<style>`，再用「标记 → `</style>`」范围替换来更新 | 把标记之后的用户 CSS 全吃掉，页面悄悄退回旧样子 | 工具的产物独占一个容器（自己的 `<style data-xxx>` 或成对哨兵），整块替换 |
| 用 XML 解析器验含内联 SVG 的页面 | 报 `not well-formed`，但页面完全正常（无值布尔属性在 HTML5 合法、XML 不合法） | 用 HTMLParser 或直接在浏览器里量 |
| 用 HTMLParser 扫内联 SVG | 一堆 `</path>` 假报错 | 内联 SVG 单独验，HTMLParser 扫剩下的部分 |
| 把 `<a href="https://…">` 算成「违反单文件约束」 | 自检误报 | 只检查 `<link>` / `<script>` / `<img>` / `<iframe>` 的 `href` / `src` |
| `background:none;border:0` 的按钮没写 `color:inherit` | 深色主题下文字是黑的，几乎看不见 | 这类按钮显式写 `color:inherit` |
| 拿输出文件名当标题 | 文件叫 `index.html` 时标题成了「index」 | 文件名是 `index` 时退回目录名，或显式传标题 |
| 用 headless Chrome 的 `--screenshot` 截带 `#锚点` 的页面 | 截出来空白或顶栏错位，页面本身没问题 | 用 puppeteer：`page.goto(url+'#锚点')` 后再 `page.screenshot` |
| 删一条规则只在手上那份文件里查残留 | 同一条规则常写在多份文件里，漏掉的那份长期指错 | 全仓 grep；中文数字 / 阿拉伯数字、大小写一起搜 |
