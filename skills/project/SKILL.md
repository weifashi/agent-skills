# 项目档案：需求背景、决策、AI 规则都跟着项目走

**以后的 Agent 只读「需求背景原文 + 代码」就该知道这个项目的初衷。** 所以需求背景能存原文就存原文；决策一行一条；架构只留最终总结；过程（计划、讨论、验收记录）不存，留在对话和提交说明里。

资料只放项目仓库里。不放外部笔记服务，不放只在本机的目录，不靠工具的自动记忆（它只存在本机，换机器、换人、换工具就没了）。

## 目录约定

```text
项目/
├─ AGENTS.md              AI 规则，Claude Code 和 Codex 都读
├─ CLAUDE.md              只有一行：@AGENTS.md
└─ docs/
   ├─ background/         需求背景原文，一次需求一个文件：YYYY-MM-DD-短标题.md
   ├─ decisions.md        决策记录，一行一条
   ├─ architecture.md     架构的最终总结，一页以内      ┐
   ├─ mockups/            原型、改动汇报（mockup 技能）  ├ 用到时才建
   └─ bugs.md             提测检查的问题清单（bug-hunt） ┘
```

起项目时只建前四样，不预先建空文件。项目已有等价的文件（如 `requirements.md`、`docs/adr/`）就沿用，在 AGENTS.md 里指过去，不为了对齐本约定搬家。

## 起新项目

1. **看现状**：目录是不是空的、有没有已有规则和文档、当前分支和未提交改动。已有的保留。
2. **存需求背景**：把用户这次讲的原话、贴的文档、聊天记录，照 `assets/background.md` 存成 `docs/background/YYYY-MM-DD-短标题.md`。这一步在写任何代码之前做。
3. **记决策**：对话里用户已经拍板的事，照 `assets/decisions.md` 各记一行，状态「有效」。你按默认先做了、用户还没点头的也记，状态写「待确认」，交付时列给用户。只是建议、还没做的不记。
4. **建 AI 规则**：照 `assets/AGENTS.md` 生成，只填查得到的事实（命令要实际跑得通）；查不到的小节删掉，不留空壳。旁边建只含 `@AGENTS.md` 的 `CLAUDE.md`。
5. **交付**：告诉用户建了哪几个文件、各存了什么、哪些内容是你推断的。

## 接手旧项目（补档案）

顺序同上，但材料要自己找：读 README、已有文档、提交记录、issue / PR、代码。

- 找得到原话的（issue 正文、PR 描述、提交说明、旧文档）原样引用并写来源。
- 找不到来源、只是从代码看出来的，写进「一句话理解」并标 **推断，待确认**。代码只能证明做了什么，不能证明用户当初要什么。
- 不编访谈、不编日期、不编「当时的考虑」。查不到就写「没查到」。
- 一个项目补一份总的背景文件就够（`YYYY-MM-DD-项目由来.md`，日期写补档这天），不按历史逐条倒填。

## 之后怎么维护

这些规矩已经写进生成的 AGENTS.md，所以以后不触发本技能也会照做：

| 发生了什么 | 写到哪 | 怎么写 |
|---|---|---|
| 来了新需求（新功能、改已有行为、改范围） | `docs/background/` 新文件 | 动手前先存原话 |
| 对已有需求的补充、改主意 | 那份背景文件的「后续补充」 | 追加日期 + 原话，不动前面的原文 |
| 用户拍板 | `docs/decisions.md` | 追加一行；之前是「待确认」的那行改成「有效」 |
| 推翻旧决定 | `docs/decisions.md` | 追加新行；旧行不删，状态改成「已被 Dxxx 取代」 |
| 阶段做完、结构有变化 | `docs/architecture.md` | 整篇改成现状，不追加、不留历史 |
| 命令、约定、边界变了 | `AGENTS.md` | 原地改，保持 200 行以内 |
| 修 bug、改文案、调样式这类小改 | 提交说明 | 不建背景文件 |

## 各文件的写法

**需求背景**（`assets/background.md`）
- 「原文」一字不改：口语、错别字、重复都保留，多条消息按时间顺序排。存了就不再改写，只在「后续补充」追加。
- 「一句话理解」是你的复述（要什么、为什么、怎样算做到），可以随理解更新。原文和复述分开，读的人才分得清哪句是用户说的。
- 贴来的长文档、截图放同名目录 `docs/background/YYYY-MM-DD-短标题/`，正文里链过去。
- 原文里的密钥、密码、他人的手机号等换成 `<已隐去：是什么>`。仓库是公开的时，存之前告诉用户原话会被公开。

**决策**（`assets/decisions.md`）
- 只记会影响后面怎么做的决定；「没选什么」写上，以后才不会被反复提起。
- 「谁定的」如实写：用户拍板，还是 Agent 按默认做的。Agent 按默认做的一律状态「待确认」，用户点头后改成「有效」并把「谁定的」改成用户。

**架构总结**（`docs/architecture.md`，用到时才建）
- 一页以内：有哪些模块、数据怎么流、对外接口、部署在哪、关键取舍（指向决策编号）。
- 只写现状和结论。方案比较、设计过程、接口明细不写；从代码一眼能看出来的目录结构也不写。

**AGENTS.md**（`assets/AGENTS.md`）
- 只写从代码看不出来、整个项目都适用的规矩；要具体到能照着做。
- 200 行以内。需求不写进来（指向 `docs/background/`），进度不写进来。

## 易错点

- 把用户的话润色、归纳之后当「原文」存 —— 原文就是原文，归纳写在「一句话理解」。
- 把自己定的事记成「有效」 —— 用户没点头的只能是「待确认」；还没做的建议不进 `decisions.md`。
- 一口气建一堆空模板 —— 用到才建。
- 把计划、会议记录、验收过程也存进 docs —— 这些不存。
- 改主意时去改原文 —— 追加「后续补充」，并在 `decisions.md` 记一行。
