# 调研：用 DataForSEO 取数

整轮调研（一个主市场 + 两三个次要市场）花费通常在 1–3 美元。开工先查余额；预计超过 5 美元先告诉用户。

## 接口和用法

通过 DataForSEO MCP 的 `api_request` 调用。每次只取需要的量：`limit` 设小，能用过滤条件就用。

| 要回答的问题 | 接口 | 要点 |
|---|---|---|
| 一批词的搜索量、难度、出价 | `POST /v3/dataforseo_labs/google/keyword_overview/live` | 一次可放几十个词；最便宜，先用它 |
| 从种子词扩出更多词 | `POST /v3/dataforseo_labs/google/keyword_suggestions/live` | 设 `limit`（如 50）和搜索量下限，不然返回很大 |
| 一个词的谷歌前 10 名 | `POST /v3/serp/google/organic/live/regular` | `device` 用 `mobile`，`depth` 设 10；只查主词，一个词一次 |
| 竞品整体体量 | `POST /v3/dataforseo_labs/google/domain_rank_overview/live` | 一次只能一个域名 |
| 竞品靠哪些词排名 | `POST /v3/dataforseo_labs/google/ranked_keywords/live` | 加过滤 `rank_group <= 20`，按搜索量倒序，`limit` 40 |

请求体是数组，例如：

```json
[{"keywords": ["词1", "词2"], "location_code": 2792, "language_code": "tr"}]
```

国家和语言用 `location_code` + `language_code`。不确定代码时查 `/v3/dataforseo_labs/locations_and_languages`。

## 容易踩的坑

- **Live 接口一次只处理一个任务**：数组里放多个任务，后面的会被忽略，只返回第一个的结果。要查 5 个域名就调 5 次。
- **不是每个国家都支持每种语言**：例如某国 + 英语可能直接报 `Invalid Field: 'language_code'`。换成该国的主语言，或把「该国的英文搜索量」写进「没查」。
- **返回太大**：扩词和排名词动辄十几万字符，会被存成文件而不是直接显示。用脚本读文件，只打印「词、搜索量、排名、落地页」这几列。
- **手机端前 10 名的网址常是谷歌的跳转链接**：看 `breadcrumb` 字段才是真实域名。
- **原始数据存档**：放在 `research/<日期>-<主题>/data/`，文件名带国家和日期。报告里的每个数字都能回到某个文件。

## 读数据时怎么判断

- **搜索量是估算值**，近 12 个月平均。当成量级看，不要当精确数字。
- **难度低 + 出价高** = 好机会：有人愿意为这个词付广告费，但自然排名竞争不激烈。
- **前 10 名的构成**比搜索量更能说明意图：
  - 全是新闻、政策解读 → 搜的人在了解信息，不是买家。
  - 全是工具站、论坛、小站 → 没有强对手，新站有机会。
  - 前几名在投广告 → 这个词能带来付费客户，做上去等于省下广告费。
- **看竞品的落地页地址**，不只看词：某个竞品靠一个首页排几个主词，说明竞争弱；靠成百上千个客户页面排长尾词，说明有一种结构性的做法值得告诉用户（那通常是产品决定，要用户拍板）。
- **品牌词不抢**（搜竞品名字的人是去找那个竞品的），最多做事实对比页，排在后面。

## 报告怎么写

第一屏一张表，回答：

| 要判断的事 | 结论 | 把握 | 最关键的依据 |
|---|---|---|---|
| 主攻词（主市场） | 哪几组，各多少月搜索量 | 高 / 中 / 低 | 难度、前 10 名是谁 |
| 第二组词 | | | |
| 不碰的词 | 哪些、为什么 | | 前 10 名的构成；功能没接通 |
| 各语言版本 | 哪个主攻、哪个暂缓、哪个不当搜索目标 | | 出价、当地对手 |
| 最强反证 | 最可能证明判断错了的事 | | 例如：新域名通常要几个月才排得上 |

后面接：下一步（谁、做什么、什么时候看结果）和**什么时候停**（带数字和日期，例如「上线 12 周后主页面月展示不足 1000 次就停写新内容」）。

正文再放：现状的硬问题、机会表（影响 × 难度）、谁在排前面、页面—关键词表、其它语言、90 天顺序、没查的事项。
