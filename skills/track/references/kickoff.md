# 开工表和任务单

## 开工表

能从代码、现有页面里查到的自己查；剩下的一次问清。

| 项 | 说明 |
|---|---|
| 要做的决定 | 拿到数据以后打算改什么：改落地页、调渠道预算、修注册流程、判断功能留不留人 |
| 现状 | 现在有没有埋点、用的什么（第三方脚本 / 自己的接口）、有哪些事件 |
| 存在哪 | 第三方平台，还是自己的后端。自己存需要：一张表、一个收集接口、一个报表页 |
| 产品有哪几端 | 官网、后台、App、给终端顾客的页面；各端的登录方式 |
| 漏斗终点 | 「激活」怎么定义（第一次真实使用）、「付费」怎么定义 |
| 目标国家 | 决定隐私法和同意框的做法 |
| 来源标记 | 现在的推广链接带什么参数（utm、落地页编号、合作伙伴编号） |
| 报表给谁看 | 在哪个后台看、谁有权限 |
| 广告 | 投不投、投哪家、要不要回传转化 |
| 环境 | 测试和正式的数据是否分开 |

## 可以直接转发给 AI 的任务单

把方括号里的内容换成项目信息，整段发过去。

```text
请帮我给一个项目做埋点和推广统计。目标是：看清用户从哪来、走到哪一步、在哪一步走掉，用来改推广页和产品。

【项目信息】
- 项目名和一句话介绍：[填写]
- 代码位置，有哪几端（官网、后台、App 等）：[填写]
- 用户从第一次访问到付费，大致经过哪些步骤：[填写，不清楚就写「请你从代码里梳理」]
- 「激活」的定义（用户第一次真正用起来的动作）：[填写]
- 目标国家：[填写]
- 现在有没有埋点，用的什么：[填写]
- 数据存在哪：[自己的后端 / 某个第三方平台 / 请你建议]
- 以后投不投广告，投哪家：[填写]

【请按这个顺序做】

第一步：只出方案，不改代码
1. 梳理现状：现在有哪些埋点，各自发到哪。
2. 画出从访问到付费的漏斗，10 步左右，每一步对应一个看得见的用户动作。
3. 列一张事件表，每个事件一行：事件名、哪一端发、什么时候发、带哪些字段、用来做什么决定。现有事件逐个标「保留 / 修改 / 删除」并写原因。说不出用途的事件不要。
4. 说明身份怎么分级：不经同意能记什么、同意后多记什么、登录后按账号记什么。
5. 列出明确不记的东西（例如 IP、邮箱、金额、自由文本）。
6. 按目标国家的隐私法说明同意框怎么做，并注明哪些需要法务确认。
7. 说明报表有哪些页面，每个页面用来做什么决定。

第二步：我确认方案后再实现
1. 收集接口：
   - 每一端只收它该发的事件，未知事件丢掉并计数；
   - 注册成功、第一次使用、付费这类关键事件，必须带着有效登录且是本人账号才收，防止被伪造；
   - 每个来源和全站都有每天的数量上限，统计不能把业务数据库写满；
   - 过滤机器人；自己人的设备可以标记为不统计；
   - 统计出任何问题都不能影响页面正常使用。
2. 前端：
   - 没同意之前不在用户设备上写任何非必要的记录；
   - 关键事件每个账号只记一次，刷新、重新登录不能重复记；
   - 推广链接里的来源参数要一路带到注册完成。
3. 报表：漏斗、按来源、落地页、访客路线；再加一个「导出给 AI 分析」，把数据和每个数字的口径一起导出。
4. 需要建表或改数据库的，先告诉我，等我同意再执行。

第三步：上线和验证
1. 测试环境和正式环境的数据分开。
2. 上线后发一条测试事件，确认能入库、能在报表里看到。
3. 上线前自己人测试产生的数据，列出条数，问我要不要清；清之前先备份。
4. 把事件表写成文档放进代码库，以后加功能就在里面加一行。

【沟通要求】
- 全程用中文，像给不懂技术的老板讲。讲「谁从哪来、在哪一步走掉」，不要只讲事件名。
- 每完成一步先汇报结论，再说依据。需要我决定的事单独列出，并给建议。
- 哪些数现在还看不到（功能没接通、样本太少），要明说。
- 做完了、验证了什么，如实说；没验证的也如实说。
```

填的时候注意：

- 「激活」的定义最重要。它定错了，整个漏斗的后半段都没有意义。
- 如果已经在用第三方统计并且不打算换，在「数据存在哪」里写明，AI 就不会去建自己的表和接口。
